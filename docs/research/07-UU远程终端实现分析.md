# 07 · 网易 UU远程「终端」是怎么实现的

> 调研日期：2026-09-03 ｜ 触发原因：`docs/research/01` 与 `docs/02` §4.1 中「UU远程仍是单机 shell、无会话保持语义」的判断需要核实
> **核实盲区（重要）**：本次 `uuyc.163.com`、`blog.csdn.net`、`sspai.com`、`cloud.tencent.com`、`www.cnblogs.com`、`dqtx.cc` 全部被出口代理拦截，**无法打开任何一手页面**。以下全部来自搜索引擎对这些页面的摘要，属二手转述。落地前必须自己装一个实测。

---

## 0. 一页结论

1. **机制**：UU远程的终端不是新开一条通路，而是在被控端常驻客户端**已经建好的 P2P / 中转通道上多路复用一条纯文本流**；客户端在登录用户的会话里用系统伪终端起一个 shell 子进程，把字节流转发给控制端渲染。它和游戏串流复用同一套引擎，只是把「视频帧」换成「终端字节」。
2. **它和 terminalX 的被控端架构几乎同构**：常驻客户端 + 出站连接 + 用户会话内的 PTY + 进程内缓冲的 detach/attach + 客户端死则会话死。
3. **我们此前的判断有一处错**：UU远程**有**会话分离与重新接入，不是「无会话保持语义」。这条要从文档里改掉（已改，见 §7）。
4. **仍然成立的差异**：UU远程是一个**哑终端**——没有「谁在等我确认」的概念，没有 hooks 集成、审批收件箱、推送通知，没有多机 × 多会话的一屏总览，不是 Web 页面（原生客户端），不可自建（数据流经网易账号与服务器）。
5. **新增的风险**：官方 CLI 文案已出现「嵌入批处理、Shell、**AI 流程**实现全自动无人值守管控」的表述，产品方向在往开发者 / 自动化靠。若网易给终端加上「命令完成 / 等待输入」的推送提醒，我们的差异会进一步收窄。
6. **它有而我们没有的**：端口映射。对远程办公其实很实用，值得进路线图候选。

## 2. 终端功能（2026-05 前后上线）

### 2.1 已证实的行为

- **定位**：控制端直接访问被控端的命令行环境（终端 / PowerShell），无需图形界面。
- **零配置**：官方原话「无需 SSH、无需公网 IP、无需安装额外软件」。
- **纯文本传输**，带宽远低于视频流；PC 与手机都能用。
- **会话分离与重新接入**：
  - PC 端直接关闭终端窗口，远端命令继续运行；
  - 移动端关闭时选「退出页面」，不要选终止被控端的命令行；
  - 再次点击终端入口，若被控端命令行进程仍在运行，提示「**接入已有会话**」。
  - 官方给的场景就是「跑编译、跑测试、跑数据迁移时，发起命令后直接分离」。
- **限制（官方原话）**：「若被控端重启了程序或命令行进程已退出，之前的会话历史将无法恢复，只能新建命令行。」
- **被控端要求**：建议 Windows 10 64 位 / 11；**需确保系统账号已登录**。
- **退出方式**：点右上角 × 或输入 `exit`。

### 2.2 我的推断（无一手证据，标注为推断）

| 推断 | 依据 |
|---|---|
| Windows 侧用 **ConPTY** | 要托管 PowerShell 并支持 resize 与彩色输出，Win10 1809+ 只有这一条官方路径 |
| 终端**复用已有的远控连接通道** | 端口映射的官方措辞明确是「复用已有的远控连接通道，无需额外部署」；同一引擎下终端没有理由另起炉灶 |
| 会话保持 = **客户端进程内持有 PTY + 输出缓冲**，控制端只是 attach / detach | 正好解释了官方那条「客户端重启会话就没了」的限制 |
| shell **以登录用户身份在用户会话内**启动（非 Session 0 服务） | 锁屏验证与「需系统账号已登录」两条硬要求；这与我们受 microsoft/terminal #11865 约束的结论一致 |

### 2.3 数据路径（推断）

```
控制端（PC / 手机原生 App，内嵌终端仿真器）
   │  UDP + 私有协议；P2P 优先，失败降级网易中转节点
   ▼
被控端 UU远程客户端（常驻，已登录网易账号）
   │  同一条连接多路复用：视频流 / 终端文本流 / 端口映射 TCP 隧道
   ▼
系统伪终端（Windows 推断为 ConPTY）→ PowerShell / cmd
   以登录用户身份运行；锁屏时需先通过锁屏验证
```

## 3. 安全模型

- **锁屏验证**：进终端时若被控端处于锁屏状态，**必须完成一次锁屏验证**——手动输入被控端系统账户密码，或由已开启的「自动解锁」功能用已记录的密码代填。
- macOS 需在系统设置的「辅助功能」「录屏与系统录音」中授权。
- 有设备锁、独立访问密码、隐私屏、连接记录可追溯、「远程协助期间自动锁定客户端」。
- **无 2FA**：第三方横评口径称 UU远程暂未提供二次验证（**待核实**）。

**对我们的意义**：这条锁屏验证是很聪明的设计——它把「远程开终端」和「本机物理安全」绑定，值得借鉴到 terminalX 的安全叙事里（我们目前是设备配对 + Passkey，没有把被控端本机凭据纳入）。但它也说明 UU远程的终端和我们一样**受限于登录用户会话**，不是服务级。

## 4. CLI 工具 uuyc-cli（2026-06 前后）

| 项 | 内容 |
|---|---|
| 位置 | `uuyc-cli.exe`，在软件安装目录 `bin` 下 |
| 覆盖能力 | 官方口径「本地设备、云电脑、**远程 Shell**、远程协助」四大类 |
| 已知命令 | `uuyc-cli echo`（连通测试，返回应答文字即正常）、`uuyc-cli device list`（JSON，含 deviceId、名称、`isOnline`）、`uuyc-cli version` |
| 认证 | 绑定网易登录账号，需提前在主客户端登录 |
| **硬约束** | 绝大多数命令**依赖主客户端打开运行**，关闭主程序返回**退出码 2**；仅 `version` 无需主程序 |
| 定位话术 | 「可嵌入批处理、Shell、**AI 流程**实现全自动无人值守管控」 |

**对我们的意义**：这是最值得警惕的一条。它说明网易已经意识到「开发者 + 自动化 + AI」是这个功能的用户群。但 CLI 只是「让脚本去调远控」，仍然没有反向的「agent 需要你确认时通知你」——这正是我们的位置。

## 5. 端口映射（2026-04/05）

- 把远端设备（或其所在局域网）的 **TCP** 服务映射到本机端口。
- 官方口径：图形化操作、零配置、**复用已有的远控连接通道**、免费。
- 目前**仅 Windows 主控端、仅 TCP**，更多平台与协议在开发中。
- 媒体定位是「告别 frp 和 ngrok」。

**对我们的意义**：terminalX 没有这个功能。远程办公场景里它很实用（把远端 dev server、数据库端口拉到本地）。而且我们的架构（被控端出站长连接 + 中转路由 + 二进制帧）加一个 TCP 隧道帧类型就能做。**建议列入 1.1 / 2 期路线图候选**。

## 6. 与 terminalX 的逐项对照

| 能力 | UU远程 | terminalX 第一阶段 | 判断 |
|---|---|---|---|
| Windows 零配置终端 | ✅ 已上线 | ✅ | **被覆盖** |
| 会话 detach / attach | ✅（客户端重启即丢） | ✅（同样的短板，但有 `--resume` 拉回） | **基本被覆盖**，我们只多出「重启后拉回」 |
| 纯文本而非像素 | ✅ | ✅ | **被覆盖** |
| 手机可用 | ✅ 原生 App | ✅ PWA | 打平 |
| 免公网 IP / 免 SSH | ✅ | ✅ | 打平 |
| 国内可达 | ✅ 网易节点，比我们强 | ⚠️ 需自己买 VPS | **我们更弱** |
| 端口映射 | ✅ | ❌ | **我们缺** |
| CLI 自动化 | ✅ | ❌（有 `doctor` 等，但非远控 CLI） | 我们缺，优先级低 |
| **AI 感知（等你确认 / 收件箱 / 推送）** | ❌ 完全没有 | ✅ | **我们的核心差异** |
| **多机 × 多会话一屏总览** | ❌ 选设备 → 开终端 | ✅ | **我们的差异** |
| **Web 页面（浏览器打开即用）** | ❌ 原生客户端 | ✅ | **我们的差异**（用户明确要 Web） |
| **可自建 / 数据不经第三方** | ❌ 强绑网易账号与服务器 | ✅ | **我们的差异** |
| **供应商预设（中转 Key / MiniMax 端点注入）** | ❌ | ✅ | **我们的差异** |
| **免包装器附着到已有会话** | ❌ 只能它自己起的 shell | ✅（Claude hooks） | **我们的差异** |
| 崩溃 / 重启后自动拉回 | ❌ 明说会话丢失 | ✅ `claude --resume` | 我们的差异 |

**结论**：UU远程把「远程开一个终端」这件事本身做完了，而且做得比我们早、比我们省事。terminalX 的存在理由必须**完全押在 AI 感知层与控制塔视图上**，不能再靠「Windows 上能远程开终端」这个基础能力叙事。

## 8. 待你实测确认的问题

代理拦截导致本次拿不到任何一手页面，以下都需要你装一个 UU远程亲自验证：

1. **手机端终端能不能正常操作 Claude Code 的 TUI**——方向键选权限选项、`Esc` 中断、`Shift+Tab` 切模式、中文提示词输入。这是决定它能否替代 terminalX 的**关键问题**。
2. 终端是否支持**多标签 / 同一台机器多个并发会话**（本次没有任何资料提到）。
3. 被控端**无显示器 / 无人值守**时终端是否可用（锁屏验证能否用自动解锁绕过）。
4. Linux / macOS 被控端是否支持终端功能（资料只明确了 Windows）。
5. `uuyc-cli` 的**完整子命令列表**，尤其是「远程 Shell」那一类的参数与输出格式（是否 JSON、能否非交互批量执行）。
6. 断线重连时的**输出补差**行为：是否会丢字节、有没有滚动缓冲回放。
7. 免费额度是否真的无限制（终端与端口映射是否会在未来变成付费功能）。
