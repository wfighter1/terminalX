## 1. 选型决定

| 部件 | 选型 | 理由 | 切换条件 |
|---|---|---|---|
| **被控端 Agent** | **Go 1.26+ 单 exe（当前稳定 1.27，go.mod 用 `toolchain` 锁定）**（`GOOS=windows` 交叉编译，无 cgo）；ConPTY 用 `charmbracelet/x/xpty` v0.1.4 起步（统一 conpty / unix 接口），需要 `CreateProcessAsUser`、自带 `conpty.dll` 双路径或自定义 teardown 时下沉到 `x/conpty` 层自改；`coder/websocket` v1.8.15 出站 WSS | 第 4 周就能把一个零依赖 exe 发给别人装：不需要 Node SEA（Stability 1.1）、native 侧车、Inno Setup，也不继承 node-pty 2026-07/08 新开的四个 ConPTY 泄漏 / teardown issue；常驻内存小；macOS / Linux 被控端换 `creack/pty` 即得单二进制 | 若开发者本人是 TypeScript 原生开发者、不熟 Go 的 Windows 系统调用，**结论翻转为 Node 24 + node-pty 1.1.0**（见 `architecture-options/node-rust.md`），协议不变。量化切换：PTY 宿主 24 小时 RSS 增长 >200 MB 或每周崩溃 >1 次 → 切自带 `conpty.dll` 路径，再失败切 node-pty 侧车宿主 |
| **中转 Relay** | Go 单二进制：`net/http` + `coder/websocket` 路由；`modernc.org/sqlite` v1.58.0（纯 Go）；⚠️ `go-webauthn/webauthn` Passkey + `pquerna/otp` TOTP **未实现，当前是单一管理密码**（见 §0.2）；Caddy 自动证书；Docker compose 一条命令 | 国内廉价 VPS 自建友好；供应链依赖树小 | — |
| **Web 控制端** | React 18 + TypeScript + Vite PWA；`@xterm/xterm` 6.0.0 + addon-fit / webgl / search / serialize（`windowsPty` 启发式）；共享 `packages/protocol`（由 Go `internal/proto` 生成 TS 类型与帧编解码，用 tygo 或模板） | xterm.js 6.0 移除 canvas、加 DEC 2026 同步输出，是唯一合理选择 | 协议类型生成漂移 → 改为手写 zod schema 双向校验 |

**核心立场：** Agent 只做「会话宿主 + 字节搬运 + 事件登记」；中转只做「路由 + 元数据」；AI 感知优先 hooks / notify 结构化信号，PTY 文本解析只作带置信度的兜底，绝不驱动自动决策。

## 3. 协议

单条出站 WSS 复用多会话。控制面 JSON 文本帧，数据面二进制帧。

### 3.1 控制面（JSON）

```jsonc
// Agent → Relay
{"t":"agent.hello","agent_id":"…","version":"0.1.0","os":"windows","caps":["conpty","hooks.http"],"sessions":[…]}
{"t":"heartbeat","heartbeat":{"seq":1234,"sent_at":"…","power":"ac","sessions":[{"sid":1,"pty_alive":true,"last_output_at":"2026-09-03T03:01:10Z","seq":88213}]}}   // 中转原样回显，被控端据 sent_at 算 RTT
{"t":"session.state","sid":"s1","state":"needs_input","kind":"permission","source":"hook","confidence":"high"}
{"t":"approval.new","sid":"s1","key":"…","tool":"Bash","input":{"command":"go test ./relay/..."},"cwd":"D:\\work\\terminalx","mode":"remote_first","hook_timeout_at":"…"}   // 仅 remote_first 有意义：hook 超时回落本机对话框的时刻，卡片届时转为「已回落」而非消失
{"t":"approval.closed","key":"…","by":"local"}          // 本机答过 → 控制端自动关闭卡片
{"t":"session.exited","sid":"s1","code":0,"resumable":{"tool":"claude","name":"terminalx"}}

// 控制端 → Relay → Agent
{"t":"session.open","req_id":"…","device_id":"…","open":{"shell":"pwsh","cwd":"…","tool":"claude","preset":"minimax","permission_mode":"acceptEdits","name":"terminalx","approval_mode":"notify"}}   // 被控端回 session.opened 时回带 req_id 与 client_id
{"t":"session.attach","sid":"s1","last_seq":88213}      // 补差；差距过大则收 SNAPSHOT
{"t":"session.resize","sid":"s1","cols":120,"rows":40}
{"t":"session.signal","sid":"s1","sig":"esc|ctrl_c|eof|kill_resume"}      // Windows 无 SIGTERM，kill_resume 的路径见 §5 进程语义
{"t":"approval.decide","key":"…","decision":"allow|deny"}   // 仅 remote_first 会话
// 配对不走 WebSocket：控制端 POST /api/pair/new 取码；被控端 `tx-agent pair --code` POST /api/pair/redeem {code,name,os,agent_version,pubkey} → {device_id,device_token,fingerprint}
```

以上为示意；字段名以 `internal/proto/messages.go` 为准（实现已落地，见 §7）。

### 3.2 数据面（二进制帧，18 字节头）

```
| ver u8 | type u8 | flags u8 | reserved u8 | sid u32 | seq u64 | len u16 | payload … |
type: 1=OUTPUT 2=INPUT 3=RESIZE 4=SNAPSHOT 5=EOF(exit code) 6=ACK
ver ≠ 1 → 直接断连（fail-closed）；payload 从第一天按不透明字节处理，1.1 逐帧加密不改帧头。
```

- Agent → 控制端方向 10–16 ms 合批，削 Ink / ratatui 全量重绘峰值。
- ⚠️ 背压（**设计，未实现**）：按客户端 64 KiB ACK；某客户端未确认超 1 MiB 只对它停发，恢复时改发 SNAPSHOT；绝不暂停 PTY。**现状**：Ack 帧只做 per-sid 记账，没有按客户端限流——中转按 sid 路由，本身也区分不出客户端。见 §0.2。

### 3.3 会话保持

Agent 持有 PTY + 4 MiB 环形缓冲 + 单调 `seq`。控制端 attach 带 `last_seq`：在缓冲内 → delta 补差；否则 → `ESC c` + 回放缓冲尾部（SNAPSHOT），随后发一次 `cols±1` 的 resize 抖动强制 TUI 重绘（tmux 做法），对 alt-screen 应用（Claude 在 NO_FLICKER 模式下正是 alt-screen）纳入第 4 周验收。多端同时附着共享同一缓冲。

### 3.4 状态机

`running` / `needs_input(permission | question)` / `idle` / `failed`（StopFailure）/ `exited` / `quota_wait`（仅 claude.ai 登录）/ `unknown`。每个状态带 `source ∈ {hook, hooks_json, notify, statusline, pty_heuristic}` 与 `confidence ∈ {high, low}`。低置信「疑似」（输出停顿 ≥5 分钟且末行匹配提示符模式）去抖 15 秒。`unknown` 触发条件：心跳正常但 >10 分钟无结构化信号且无输出；末行匹配提示符模式时优先判「疑似」而非 unknown。

## 4. 安全设计

| 层 | 设计 |
|---|---|
| 网络 | Agent 只出站 443；hooks 端点仅 127.0.0.1；无入站端口，不触发防火墙提示；支持 `HTTPS_PROXY` |
| 配对 | **已实现**：8 位一次性码（5 分钟，错 5 次锁 15 分钟），用户在被控端 `tx-agent pair --code` 输入；被控端生成 X25519 密钥对并上报公钥；两端各自按 `sha256(pubkey)` 的 base32 前 8 位算出同一个指纹短码，目视比对。<br>⚠️ **未实现**：ECDH 共享密钥协商与 HKDF SAS 派生（当前指纹不来自共享密钥）；`install.ps1 -Code`；二维码。见 §0.2 |
| 凭据 | **已实现**：控制端单一管理密码（SHA-256 + 常数时间比较 + 登录失败锁定）；设备长期 token 哈希存中转。<br>⚠️ **未实现**：Agent 侧 DPAPI 加密（token 明文存 `agent.json`，仅靠 0600 权限）；Passkey / TOTP；敏感操作 10 分钟内重认证。见 §0.2 |
| 端到端加密 | **现状：未实装**——第一阶段 TLS 到中转，中转可见明文终端内容，内容不落盘；1.1 实装 X25519 → HKDF → 方向密钥 → AES-256-GCM 逐帧，nonce = sid‖seq，校验失败即断不降级（对照 RustDesk 验签失败继续明文的反例）。**托管或多人使用前的硬门槛**；托管形态下前端由中转分发，需 SRI + 可复现构建，且如实说明「零知识对用户不可验证」 |
| 审计 | 中转 SQLite `approvals` / `audit` 两张表：谁 / 何时 / 哪台设备 / 哪个会话 / 动作 / 结果；不含终端内容 |
| 权限 | 远程 ≤ 本地硬规则；bypassPermissions 会话不触发 hook |
| 供应商预设 | 环境变量（`ANTHROPIC_BASE_URL`、`ANTHROPIC_AUTH_TOKEN` 等）由 Agent 在本机注入子进程，不经中转明文；hook token 经 `headers` + `allowedEnvVars`（`$TX_TOKEN` 由 Agent 注入）传递，不明文写入文件 |
| 表结构 | 单用户模型预留 `user_id`，为团队版留位 |

## 5. Windows 细节

| 主题 | 决定 |
|---|---|
| ConPTY | Windows 10 1809+（与 Claude Code 系统要求一致）。默认系统 ConPTY；可切自带 `conpty.dll`（NuGet Microsoft.Windows.Console.ConPTY，注意 node-pty #894 报告自带 DLL 首屏约 3.8 秒 vs 系统 340 ms）。teardown 顺序：先关输入管道 → `ClosePseudoConsole` → 等进程；用 xpty 的 `WaitProcess` 处理等待怪癖 |
| 默认 shell | pwsh 7 → Windows PowerShell 5.1 → cmd；Git Bash / WSL 尽力。按会话选 shell，对假设 POSIX 的工具默认给 Git Bash |
| 运行身份 | **用户会话内运行**（microsoft/terminal #11865 Open：服务替登录用户开 ConPTY 无官方路径；AI CLI 凭据在用户 profile）。任务计划程序 ONLOGON，XML 显式 `RestartOnFailure`（1 分钟 × 999）与 `ExecutionTimeLimit=PT0S`；supervisor 用 `-ldflags "-H=windowsgui"` 隐藏控制台窗口（Paseo #3389 前车之鉴） |
| 睡眠 / 重启 | 睡眠、注销、未自动登录即离线；安装向导如实告知并给 `powercfg` 建议与可选自动登录；Agent 上报电源状态；重启登录后 ≤60 秒上线，会话标「可拉回」，一键 `claude --resume <name>` / `codex resume --last` |
| Claude 渲染 | 固定 ≥100 列；注入 `CLAUDE_CODE_NO_FLICKER=1`（已核实，语义为切到 fullscreen 渲染器，滚动由 Claude 内部处理）与 `CLAUDE_CODE_ALT_SCREEN_FULL_REPAINT=1`（已核实：每帧全量重绘，官方在 Windows 的 `--bg` 与 agent view 会话自动开启）；用户 settings 里的 `CLAUDE_CODE_DISABLE_ALTERNATE_SCREEN` 优先级高于 NO_FLICKER，注入前检测并提示；不承诺 40 列 |
| 进程语义 | Windows 没有 SIGTERM / SIGINT（Go 的 `os.Process.Signal` 在 Windows 只支持 Kill）。kill & resume 的 Windows 路径：先向 PTY 写 `0x03`（Ctrl-C，结束当前 turn）→ 写 `/exit`（Claude）或 Ctrl-D 让进程正常退出（跑 SessionEnd hook）→ 5 秒超时后 `TerminateProcess` → 按会话名 `--resume`。官方 headless 页的「SIGINT 结束 turn、SIGTERM 退出码 143 且续跑」是 Unix 语义，仅用于第二阶段 macOS / Linux 被控端；「原生 Windows 下 Ctrl-C 是否结束 turn、/exit 后 --resume 是否续跑未完成 turn」列入第 1 周 spike ②。`--bare` 跳过 hooks（不用） |
| 分发 | 单 exe 自安装子命令 `install / uninstall / doctor / pair`；Authenticode 签名（Go 二进制有 Defender PUA 误报史 golang/go #51514；价格待核实）；不用 UPX；误报提交；winget 后置 |
| 编码 | 子进程 `chcp 65001` / `[Console]::OutputEncoding = UTF8`；处理 GBK 与 UTF-8 |

## 6. AI 感知层

### 6.1 Claude Code

- 注入：`claude --settings <terminalx-hooks.json>`（不改用户 `~/.claude/settings.json`），文件含 `allowedHttpHookUrls` 白名单。与 `claude remote-control` 不能同时使用，UI 明示。
- hooks（http 型，语言无关，官方默认 timeout 600 秒可配）：`SessionStart` / `SessionEnd`（登记）、`PermissionRequest`、`Notification`（matcher：`permission_prompt`、`idle_prompt`、`agent_needs_input`、`elicitation_dialog`、`quota_auto_resume_*`）、`Stop` / `StopFailure`。
- 失败模式友好：非 2xx 或连接失败为 non-blocking error，Claude 照常弹本地对话框。
- **通知模式（默认）**：PermissionRequest hook 登记 + 推送，≤10 秒返回空输出（不带决定）。
- **远程优先（每会话可选）**：hook 挂起，`timeout` 显式 3600；回写 `{"hookSpecificOutput":{"hookEventName":"PermissionRequest","decision":{"behavior":"allow"}}}`，`behavior ∈ {allow, deny}`（第 1 周用 20 行脚本实测真实 payload 与 schema）。`--bg` 会话丢弃决定（#88698），UI 禁用。
- 去重键：PermissionRequest 输入不含 `tool_use_id`（官方文档明确），主键 = `sha256(session_id‖tool_name‖canonical_json(tool_input))`，60 秒窗口合并；若同时装了 PreToolUse hook，可用其 `tool_use_id` 做关联；卡片回显 `permission_suggestions`。
- statusLine：向导可选写入一条 statusLine 命令把 JSON POST 到本地端点，只采 `cost.total_cost_usd` 与 `context_window.used_percentage`；`rate_limits` 缺失时不显示。
- ⚠️ 免包装器附着（**设计，未实现**，见 §0.2）：可选 `terminalx hooks install`，把同一份 http hooks 写入用户 settings（写前展示 diff），让用户自起的 `claude` 也能进收件箱；`SessionStart` 带 cwd 与 pid 用于匹配 PTY。

### 6.2 Codex CLI

- `hooks.json` 的 `PermissionRequest`（`Feature::CodexHooks` 已核实 Stable 且默认开启）用于审批登记；`notify` 只序列化 `agent-turn-complete`（thread-id / turn-id / cwd / last-assistant-message）用于完成事件。
- 输出 schema 已从源码核实（`codex-rs/hooks/src/engine/output_parser.rs`）：`{"hookSpecificOutput":{"hookEventName":"PermissionRequest","decision":{"behavior":"allow"|"deny","message":"…"}}}`；`updatedInput` / `updatedPermissions` / `interrupt` 不支持；多 hook 折叠规则「任一 deny 即 deny，否则最后一个 allow」。该 hook「runs in the approval path, before guardian or user approval UI is shown」，与 Claude 同构。
- 第一阶段只做「登记 + 推送 + 打开终端 + 键条」；1.1 试验 Codex 的「远程优先」直接走 hooks.json（与 Claude 同一条路），app-server 本地 unix socket（Windows 支持，current-user-only DACL；daemon 会把 pending approval 重放给新连接）作备选；WebSocket 传输官方标 experimental and unsupported，不用。

### 6.3 Grok Build

- xai-org/grok-build：Windows `install.ps1`、hooks、ACP、headless。第 1 周核实 hooks 事件名；可用则 command hook 一行 `curl` 打回环端点，否则 PTY 启发式「疑似」。

### 6.4 MiniMax 与其他

- MiniMax = 供应商预设：环境变量模板让 Claude Code / Codex 走 MiniMax Coding Plan 端点（Anthropic 兼容 / OpenAI 兼容，端点待核实）。
- OpenCode（自带 `serve` REST + SSE `permission.asked`）与 Qwen Code（与 Claude 同构 http hook）是 1.1 最省力的下一批；其余走 ACP（1.2）。

### 6.5 PTY 启发式（兜底）

- 仅用于无结构化信号的会话：输出停顿 ≥N 分钟且末行匹配 `(y/N)`、`[y/n]`、`›` 等模式 → `needs_input` 低置信「疑似」；15 秒去抖；只显示不决策。
- 统一事件经中转按 key 去重后推送；本机答过 → `approval.closed` → 控制端自动关闭。
