## 0. 一页结论

**terminalX 是什么。** 一个自己部署的「远程终端 + AI 代理监工台」：Windows 电脑上装一个被控端，它常驻托管 Claude Code / Codex / Grok Build 这些 AI CLI 的终端会话；你在任何浏览器或手机上打开一个页面，看到所有机器、所有会话的状态，处理它们「等你确认」的请求，需要时下潜到真终端。中转节点是你自己的，被控端只发起出站连接。

**给谁。** 第一阶段只服务一种人：**用 Windows 台式机跑 AI CLI、走中转站 API Key 或网关、白天不在电脑前、用手机盯任务的独立开发者**。这个人被 Anthropic 官方 Remote Control 明文排除（API Key 不支持，`ANTHROPIC_BASE_URL` 指向非官方地址即禁用），被境外开源方案的中转和 Windows 稳定性拖累，被 ToDesk / 向日葵 的「像素流」折磨。

**亮点是否成立。** 成立，但窄。三位红队一致结论：`has_real_edge = true`，置信度 0.55–0.6。真正站得住的不是任何单一功能，而是一个交集：

> **Windows 被控端常驻保活 × 任意 API 配置 × 国内可达的一条命令自建中转 × 真终端与 agent 感知收件箱双视图**

四项同时兑现才有存在理由；任何一项单拎出来都已有人做。被红队打掉的口号有三句：「Windows 上的 tmux 替身」（psmux、Zellij 0.44 原生 Windows、`claude --bg` 都在填这块）、「跨工具审批一等对象无人做」（Happier 已做）、「零知识中转」（开源侧的入场券，不是卖点）。

**第一阶段做什么。** 一个 Web 页面控制一台或多台 Windows 上的多个终端 / AI CLI 会话：断线不丢会话、手机可用、Claude Code 与 Codex 的「等你确认」推送到手机并可处理、重启后一键拉回。周期 **8–10 周**（一人），第 1 周先做三个技术验证，任一失败即降级而非顺延。

**下一步。** 动工前先用一手数据验证目标人群存在：访谈或发帖找 20 个「Windows + 中转 Key + 手机」用户。本次所有中文社区证据均为二手。

## 2. 定位

**一句话：** terminalX 是你自己部署的 AI 代理监工台——Windows 上的 AI CLI 会话常驻不掉线，手机上一屏看清谁在等你、一键处理，任何 API 配置都能远程。

**它不是：** 远程桌面（不传画面）、IM 聊天桥接（不与 cc-connect 竞争，飞书 / 企微只做告警 + 回到控制台）、云端 agent 编排（不与 Claude Code on the web / Codex cloud 竞争）。

**命名原则：** 对外自称「远程终端」而非「远程控制」，规避国内「远控 = 涉诈」语境；README 首屏放数据流向图。

## 5. 亮点判断（诚实分级）

### 5.1 结构性差异：对手因架构或动机不会做

| 亮点 | 证据（2026-09-03 核实） | 谁做不了 |
|---|---|---|
| **任意 API 配置都能远程** | 官方 Remote Control 文档：「API keys are not supported」；`ANTHROPIC_BASE_URL` 指向非 `api.anthropic.com` 即不可用（v2.1.196 起，是收紧而非放开）；Bedrock / Vertex / Foundry / ZDR 组织不可用。官方整套「离开终端」能力（RC、web、mobile、Dispatch、跨机消息、额度自动续跑）被同一条约束锁死：转录必须经 Anthropic 云同步 + claude.ai 登录 | 官方：架构使然，12 个月内放开概率低（<25%）。Happy / Paseo / Happier 也不依赖官方账号，所以这条**只相对官方成立**，是入场券 |
| **Windows 被控端：工具无关的常驻会话宿主 + 登录自启 + 崩溃 / 重启后自动拉回 + 远程解卡** | Win32-OpenSSH #2291（2024-10 开启，仍 Open、无 assignee）：sshd 断线子进程被 job object 回收，Windows 没有等价 tmux；Codex CLI 在 Windows 上 remote-control daemon 至今不可用（codex #34584、#42507 2026-09-03 Open）；Claude RC 在 Win11 静默挂起「只有本地 Esc 能救」（claude-code #51267 Open）；Paseo 2026-08 仍有四个 Windows daemon 问题 Open；Happier #256「Windows sessions never start」P1 Open | 官方各管自家工具且 Windows 滞后；开源侧正在踩坑。**窗口约 6–12 个月**。注意：不能再说「Windows 没有 tmux」——psmux（原生 ConPTY）、Zellij 0.44（原生 Windows + web client）、`claude --bg`（Windows 可用）都存在；我们多出来的是「跨工具 + 远程 attach + 手机 + 重启自动拉回 + 远程 Esc」 |
| **国内可达的一条命令自建中转 + 中文 IM 告警** | Happy 默认 relay 在境外且出过 522 全站故障（happy #105 超时）；Tailscale 在国内无官方 DERP；Cloudflare 可达性不稳 | 境外开源与官方都不会为此优化。本质是「省一次 Headscale + DERP 运维」，不是别人做不到 |

### 5.2 执行质量差异：别人有，但做得差或不在 Windows

| 亮点 | 现状 |
|---|---|
| **真终端 + agent 感知双视图** | 官方 RC 只有聊天 UI；VibeTunnel 只有终端且不支持 Windows；Happier 有内嵌终端。差异在 Windows 与工程质量 |
| **跨机跨工具收件箱 + 全局状态条「N 运行中 · N 等你 · N 出错 · N 未知」** | Happier 已有「global attention center」。我们的增量：免包装器附着（用户自己起的会话也能进收件箱）、本机答过自动关闭、Unknown 状态与置信度标注、远程 ≤ 本地 |
| **免包装器附着** | Happy / Happier 必须 `happy claude` 包装启动；官方 Agent View 仅本机仅 Claude。「我照常用我的终端，terminalX 只是多一双眼睛」是对老手唯一有说服力的姿势 |
| **手机键条 + 独立输入框** | Termius / Blink 打磨多年；Zellij web 有手机模式。我们不承诺比它们好，只承诺「看 + 审批 + 常用键 + 整行发送」可用 |

### 5.3 产品规则：不是亮点，是不犯别人的错

- **远程 ≤ 本地权限**：以 `bypassPermissions` / `acceptEdits` 启动的会话，远程端不叠加审批层（claude-code #29214、codex #30485 均 Open，官方两家都把远程当独立客户端导致降级）。实现零成本：hook 根本不会触发。
- **连接状态三信号分离**：中转↔被控端心跳、PTY 进程存活、最近输出时间各自显示，永不显示「Connected」假象（对照 #34255、#77252）。
- **审批持久且去重**：卡片不过期；本机答过 ≤2 秒自动关闭。注意官方 Claude Code 本身就会把权限提示一直挂着，「审批不过期」不是相对 tmux 的增量。
- **默认关闭、显式配对、指纹比对、只出站、审计元数据**：对个人零成本，是国内语境的信任前提。

### 5.4 被砍掉的（红队 fatal / major）

| 原方案声明 | 为什么砍 |
|---|---|
| 额度耗尽自动续跑 | 官方 interactive-mode 文档：API Key「metered per request, so there is no reset to wait for」。按量计费没有窗口可等；只有中转站自设配额的子集才有，且提示文案不统一 |
| 成本面板与 5h/7d 额度环 | statusLine 的 `rate_limits` 仅 Pro/Max 订阅或 apps gateway 才有；`total_cost_usd` 是客户端按牌价估算。核心人群看到的是一片「—」。第一阶段只在会话卡片显示两个数：`cost.total_cost_usd`、`context_window.used_percentage` |
| PTY 注入按键做自动决策 | Claude TUI 在 ConPTY → xterm.js 链路有已知重绘问题（#51828、#1913 Open），「回读屏幕确认注入成功」的前提不成立；Codex 维护者也明确拒绝 terminal scraping。**PTY 探测只显示不决策**，用户手动点键条除外 |
| E2E 实装进第一阶段 | 自建单人形态下运营者即自己；帧格式第一天按不透明字节设计，1.1 实装，任何托管或多人使用前的硬门槛。**托管形态下前端 JS 由中转分发，「零知识」对用户不可验证，不能当卖点** |
| Windows 服务化 | microsoft/terminal #11865（2021 至今 Open）：服务替登录用户开 ConPTY 无官方路径；AI CLI 凭据在用户目录。用户态登录自启是**长期约束**，不是 1.1 待办 |
| 只读分享、录制回放、三级权限、审计页 | 对画像 A「从不需要碰」；Zellij read-only token、Happier view-only 已有。1.1 / 2 / 3 期 |

## 7. 产品原则

1. **只传字节与事件，不传像素。** 需要 UAC、图形安装器、浏览器登录窗的操作在本机处理，UI 明确提示。
2. **PTY 文本探测只显示不决策。** 「疑似等待」永远是低置信提示；绝不自动注入按键；用户手动点键条是唯一的按键路径。
3. **远程权限不高于本地。** terminalX 不叠加自己的审批层。
4. **被控端只出站，hooks 只在 127.0.0.1 回环收。** 无入站端口，无 `0.0.0.0` 监听。
5. **远程默认关闭，显式配对，两端指纹目视比对，吊销即断。** 中转只存元数据。
6. **诚实的连接状态。** 三信号分离，有 Unknown（信号陈旧）状态，按信号来源标置信度。
7. **兼容而非替代。** 不改用户的 `~/.claude/settings.json`（用 `--settings` 注入）；允许用户照常用自己的终端，terminalX 可附着；不与官方 Remote Control 冲突（但 `--settings` 与 `claude remote-control` 不能同时使用，UI 明示）。

## 8. 审批模式（产品级决定）

这是红队指出的最重要的工程根基修正。官方 hooks 文档：hooks 默认阻塞 Claude 执行直到完成；PermissionRequest hook 挂起期间**原生对话框不出现**，超时后「permission flow proceeds unchanged」。Codex 的 PermissionRequest hook 同样跑在审批 UI 之前（codex #39447）。所以「hook 挂起 = 一键审批」不能是默认体验。

| 模式 | 行为 | 何时用 |
|---|---|---|
| **通知模式（默认）** | hook 只登记 + 推送，≤10 秒内返回且不带决定；终端里的对话框照常弹出。收件箱卡片标「按键」，按钮是「发送 1 ⏎ / 发送 3 ⏎ / 打开终端」，等同于坐在电脑前按键 | 人可能在电脑前；Codex 第一阶段只有这种 |
| **远程优先（每会话可选）** | hook 挂起等远程决定，timeout 显式设 3600 秒；UI 明示「开启期间终端内对话框不显示」。卡片标「hook 决定」，按钮「允许 / 拒绝」，回写 `hookSpecificOutput.decision.behavior = allow | deny` | 人确定不在电脑前（通勤、夜间） |
| **疑似** | 无 hooks 的工具：输出停顿 ≥N 分钟且末行匹配提示符模式，低置信，只提示 | Grok Build（hooks 待核实）、其他工具 |
| 硬规则 | `--bg` 会话会丢弃 hook 决定（#88698 Open），远程优先对其不可用；bypassPermissions 会话不触发 hook；本机答过 ≤2 秒自动关闭；去重键双路径（有 `tool_use_id` 用它，否则 `sha256(session_id‖tool_name‖canonical_json(tool_input))`，60 秒窗口） | — |

官方 Channels 的 permission relay 是并发通道（终端对话框保持打开，先到的答案生效），但仍是研究预览且自定义 channel 需 `--dangerously-load-development-channels`，自定义 base URL 下是否可用待核实。作为 1.1 试验路径。

## 10. 核心流程

1. **首次配对（≤10 分钟，无公网 IP）**：Web 生成配对码 + 二维码（携带一次性密钥与中转指纹）→ Windows 上一行 PowerShell 安装（普通用户）→ 输入配对码 → 两端显示同一指纹短码，目视比对 → 设备上线，远程能力此时才开启。
2. **启动一个 Claude Code 会话**：选设备 → 工具 → 目录 → 供应商预设（环境变量在被控端注入，不经中转）→ 权限模式（直接映射 `--permission-mode`）→ 会话名（映射 `--name`，本地 `/resume` 同名）→ 被控端以 `claude --settings <terminalx-hooks.json>` 拉起。
3. **手机处理一次审批**：见 §8。通知模式：点通知 → 收件箱 → 「发送 1 ⏎」；远程优先：通知上直接「允许」。
4. **断线与解卡**：浏览器断网 → 指数退避 2s→16s 重连，带 `last_seq` 补差，60 秒内逐字节一致；被控端离线 → 设备灰态、会话保留、不显示已连接；会话挂住 → 远程 Esc / Ctrl-C / kill & resume；PC 重启 → 登录自启 ≤60 秒上线，会话列表显示「可拉回」。
5. **切换机器**：左栏点另一台设备，标签可跨设备混排；零额外开发。
6. **回到工位**：本机终端答过的审批 ≤2 秒自动关闭；检测到本机键盘活动时抑制推送（第一阶段做简单版：hook 事件带 `source`，本机处理即关闭；在场检测 1.1）。
7. **中转宕机 / 家里断网**：被控端本地会话继续；恢复后补发未送达的审批与退出事件；远程优先模式下 hook 等到超时回落本机对话框。验收含「中转重启 60 秒内被控端自动重连且待处理审批不丢」。

## 16. 开源与商业化

- **许可**：Apache-2.0 开源被控端、中转、前端（不选 AGPL，避开 claudecodeui 的依赖问题）。**自建永久免费且包含全部安全能力**，避免 ToDesk 式免费额度反复缩水造成的信任崩塌。
- **第一阶段目标**：自己天天用 + 开源验证留存，**不写付费承诺**。目标人群是 niche 中的 niche，官方免费、开源免费。
- **后续假设（全部待验证）**：托管国内中转按月收费（同类锚点 CloudCLI €7 / Omnara $9 / MobileCLI $20 年，均待核实）；团队版按席位；企业私有化。托管国内节点需要 ICP 备案 + 服务器实名，「远程控制」类服务可能触发额外审查——第一阶段只提供自建。
